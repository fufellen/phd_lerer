# plasmon_fields_3d - трёхмерная визуализация полей плазмонных волноводов

Четыре сцены, показывающие поле в объёме: одиночный плазмон, связанный плазмон,
переход из диэлектрического волновода в плазмонный и фазовращатель на материале
с фазовым переходом.

Поле не рисуется по декоративной формуле. Оно берётся из провалидированного ядра
`lrspp_coupling/slabmodes`, которым воспроизведены работы Park 2008/2009/2011,
Lee 2019 и Mueller 2014, и каждая сцена перед отрисовкой проверяет саму себя.

## Запуск

```powershell
python plasmon_fields_3d/scenes/run_all.py
```

Или по одной сцене:

```powershell
python plasmon_fields_3d/scenes/scene1_single_spp.py
python plasmon_fields_3d/scenes/scene2_coupled_spp.py
python plasmon_fields_3d/scenes/scene3_dielectric_to_plasmonic.py
python plasmon_fields_3d/scenes/scene4_pcm_phase_shifter.py
```

Нужны `numpy`, `scipy`, `matplotlib`, `pyvista` (тянет `vtk`), `imageio` для GIF
и `trame` для интерактивного HTML. Отрисовка идёт вне экрана, окно не требуется.

## Что в каждой сцене

| Сцена | Структура | Главная величина | Статус |
| --- | --- | --- | --- |
| 1. Обычный плазмон | Au/ZPU450 и Ag/воздух, одна граница | спад 1341 нм в диэлектрик против 21 нм в металл | `validated` |
| 2. Связанный плазмон | Au 14 нм в ZPU450 | LR-мода живёт в 1777 раз дольше SR-моды | `validated` |
| 3. Переход в плазмонный | Au 20 нм и сердцевина ZPU13-440, зазор 5 мкм | длина связи 493 мкм, перекачка 94 % | `validated` |
| 4. Фазовращатель на PCM | SiO2 / PCM 120 нм / Au 10 нм / Si 180 нм / воздух | L_pi = 1.05, 1.79 и 1.82 мкм | `validated` |

## Чем проверяется

Всего 35 проверок, все проходят. Помимо сверки с литературой и с данными других
папок репозитория, каждая сцена подставляет своё поле обратно в уравнения
Максвелла. В нормировке `mode_fields` они имеют вид

```text
rot E = i k0^2 H,     rot H = -i eps E
```

Проверяется не абсолютная величина невязки, а её порядок по шагу сетки. Причина
в том, что абсолютный уровень задан шагом, а шаг у плазмонной задачи диктует
скин-слой металла в десятки нанометров, поэтому любой порог пришлось бы
подбирать под сцену и он маскировал бы ошибку. Если поле построено верно,
остаётся только ошибка центральной разности, и при удвоении сетки невязка падает
вчетверо. Во всех четырёх сценах наблюдаемый порядок равен 2.00.

Сверки с внешними источниками:

- сцена 1 - замкнутая формула ППП одной границы, совпадение до 1e-16;
- сцена 2 - уравнения Майера (2.29a,b), решённые отдельным ньютоновским поиском,
  и предел толстой плёнки; обе ветви прослежены продолжением по толщине на 90
  значениях и всюду совпадают с матрицей переноса до 8e-11;
- сцена 3 - теория связанных волн и значения Park et al. 2009;
- сцена 4 - значения вертикального среза S3 из `data/eim_vertical_slices.csv`
  статьи об ЭДП PCM LR-DLSPP, полученные независимой реализацией матрицы
  переноса; совпадение по Re до 5e-7, по L_pi до 0.002 %.

## Устройство кода

- `fields3d/materials.py` - оптические постоянные с указанием источника. Для
  золота хранятся два набора, Park и статейный; смешивать их нельзя, расхождение
  по Re(n_eff) плёнки составляет около 1e-3, и каждая сцена берёт тот набор, с
  которым сверяется её результат.
- `fields3d/section.py` - сечение поля в плоскости (x, z), невязка уравнений
  Максвелла, проверка порядка сходимости, поток мощности, поверхностный заряд.
- `fields3d/render.py` - сборка трёхмерной сцены из сечения.

Сечение вытягивается вдоль y, потому что структура вдоль y однородна. Объём
собирается только на этапе отрисовки: хранить трёхмерный массив незачем, а
называть трёхмерным расчётом то, что им не является, нельзя. Отрезок по y всегда
подписан как кусок бесконечно широкой структуры.

## Грабли, на которые уже наступили

Собраны здесь, чтобы не повторять.

- **Множитель k0 у E_z.** `mode_fields` возвращала E_z заниженной в k0 раз, то
  есть в 4.05 при 1.55 мкм: `v = (1/eps) dH_y/dz` несёт k0 через производную, а
  `-n_eff H_y / eps` не несёт. На результатах воспроизведения статей это не
  сказывалось, поскольку E_z входит в них только общим множителем, поэтому
  дефект и дожил до первой попытки нарисовать вектор E. Исправлено, проверка
  добавлена в `lrspp_coupling/scripts/selftest.py`.
- **Проверку сходимости надо вести по обеим осям сразу.** При измельчении только
  сетки по z вклад ошибки по x остаётся постоянным, и наблюдаемый порядок падает
  до нуля - это признак неверно поставленной проверки, а не ошибки в поле.
- **Расчётная сетка обязана разрешать саму плёнку.** Если внутри 14 нм металла
  не помещается ни одной точки с полным трёхточечным шаблоном, металл выпадает
  из проверки; при удвоении сетки он возвращается со своей крупной ошибкой, и
  порядок получается отрицательным.
- **Ветви мод надо прослеживать продолжением.** У толстой плёнки LR- и SR-моды
  вырождаются к плазмону одной границы, и поиск обеих из одного приближения даёт
  один и тот же корень. У диэлектрического слоя толще 4.6 мкм появляется вторая
  мода, и подбор толщины по приближению начинает ловить её вместо основной -
  на этом сорвалась первая версия подбора синхронизма.
- **`set_scale` не двигает камеру.** У вытянутой сцены объект после сжатия оси
  занимает около процента кадра, и `view_isometric` этого не исправляет.
  Положение камеры считается явно из границ сцены, причём `plotter.bounds`
  отдаёт границы до масштабирования, так что масштаб приходится учитывать
  вручную. Измеряется долей непустых пикселей: 0.012 у испорченного кадра
  против 0.2-0.4 у правильного.
- **Объёмный рендер миллионов узлов молча выдаёт пустой кадр.** Сетка отрисовки
  прореживается после всех проверок, а не вместо них.
- **Кириллицу VTK рисует только текстовым слоем и только с явно заданным файлом
  шрифта.** Подписи осей рисует CubeAxesActor, который файл шрифта в этой сборке
  не принимает, поэтому названия осей заданы латиницей.

## Что это не есть

Все четыре сцены планарные: слои считаются бесконечно широкими. Это точное
решение своей задачи, но не модель волновода конечной ширины. Абсолютные потери
реального прибора планарная модель не определяет - для них нужен расчёт
поперечного сечения методом конечных элементов, и он в репозитории есть
отдельно: `lrspp_coupling/scripts/fem_check_femwell.py` и провалидированный по
COMSOL пакет femwell.
